How the plugin framework works

A customer changes a 3D model through a list of steps. Each step is done by a plugin. This page shows what a plugin is, how a step runs, and how a plugin gets into an app.

Try the standalone app at ateliermesh.app: open a model, add a step, and see the plugins in the plugin manager.

A model goes through a list of steps

The engine (@ateliermesh/core) knows nothing about text, bending or hollowing. It keeps the list of steps, runs them in order, and passes the mesh from one to the next. Every step names a plugin and one operation of that plugin.

What is inside a plugin

A plugin is a small package of three kinds of file. Different parts of the app read different files, so a plugin never has to include any screen of its own.

manifest.json

Lists the operations, the settings of each one with limits and defaults, and what the plugin needs from the host, for example "uses": ["fonts"].

main.js

Exports { run }. It receives the mesh, the settings and a ctx object, and returns a new mesh.

locales

All wording sits here, in English, Dutch and French. Code never contains text that a customer sees.

How one step runs

Plugin code runs in a web worker, away from the page. It cannot reach the page, the network or the files of the customer. It gets only the mesh, the settings, and the services that its manifest asked for.

Three ways a plugin gets into an app

All three end in the same place: the registry. After that, the engine treats every plugin the same way.

Who owns which text

A plugin may only add texts under its own names. This stops two plugins from overwriting each other and keeps host wording under the host's control.

One engine, three kinds of host

The framework is a set of packages. An app picks the layers it needs. A command-line run needs no screens at all.

Beyond the mesh: drawings and stored items

A step takes one input and gives one output, and the kind of each is declared in the manifest. Most steps take a mesh and return a mesh. Some take or make a flat drawing (an SVG turned into paths), and the engine checks that the kinds fit before anything runs.

Payload kinds

Meshes and drawings travel through the same workflow. An operation says payload: { in, out }; a drawing step cannot be put where a mesh is expected, and the editor greys it out with a reason.

The project store

A project keeps named items next to its steps: imported drawings and models, and results that a Store step saves. A setting of type payload picks one by name; a Load step brings one back.

The original model

The model a project started from is always in the store under the reserved name original, read only. A Load step named original goes back to it at any point in the steps.

Catalogues and examples

The standalone app can read more than a built-in list. A catalogue is a small server folder (PHP, no database) that offers plugins, example designs, or both. Everything it offers is checked again by the app.

WhatHow it gets to a person
PluginsListed in the plugin manager with a checksum. The app downloads the file, checks it against the checksum, the manifest and the signature, shows who made it and what it needs, and asks before it installs it.
Example designsA gallery on the start page. An example is a project file; opening one gives you your own copy. If it needs a plugin you lack, the app names the catalogue that has it and asks first. An address outside the catalogues is a separate question, with the address shown in full.
SharingAnyone can send a design or a plugin to a catalogue. It waits until its admin accepts it. Nothing is listed or served before that, and the sender keeps a private key to follow it or take it back.
More than one catalogueA person can add the address of another catalogue and say what to use it for. Plugins are looked up in the order of the list; designs of all the catalogues come as one gallery.

What each person needs to know

Plugin author

Write manifest.json, main.js and the locale files. Run amplugin check and amplugin run on your computer, then pack and sign.

App developer

Pick the packages, register the plugins you trust, and pass in services such as fonts. The editor and the engine do the rest.

Customer

Sees a list of steps with settings and a live 3D view. In a shop they never see that plugins exist. In the standalone app they can also add, switch off and update plugins, and the app asks before it installs one.

See it working

The standalone app runs in your browser at ateliermesh.app. Your files stay on your device. The example gallery there shows what the plugins make.
